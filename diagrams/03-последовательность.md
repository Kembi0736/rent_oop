# Диаграмма последовательности

## Участники

| Участник | Роль |
|---|---|
| `Клиент` | актёр, инициирует заявку, залог, возврат |
| `Оператор` | актёр, единственная роль мастерской (D10) |
| `Заявка` | объект, хранит статус (D2) |
| `Залог` | объект, вход/выход денег по заявке |
| `Оплата` | объект, плата за аренду (D8) |
| `Аренда` | объект, период пользования (D6) |
| `Единица` | `ЕдиницаИнструмента`, состояние (D12) |
| `Журнал` | append-only записи (D9) |

## Основной поток

**Вопрос:** Что происходит между клиентом, оператором и системой при успешной аренде инструмента?

```mermaid
sequenceDiagram
    autonumber
    actor C as Клиент
    actor O as Оператор
    participant Z as Заявка
    participant D as Залог
    participant P as Оплата
    participant A as Аренда
    participant E as Единица
    participant J as Журнал

    C->>O: оставить заявку на перфоратор, срок N суток (D14)
    O->>Z: создать заявку
    Z-->>O: заявка «ОжидаетОбработки»
    O->>J: запись «заявка создана»

    C->>O: внести залог 3000 ₽ (D4)
    O->>D: внести залог
    D-->>Z: статус «ЗалогВнесён»
    O->>J: запись «залог внесён»

    O->>Z: обработать заявку (проверка данных, срока до 14 суток, D3)
    Z-->>O: заявка «Обработана»
    O->>J: запись «заявка обработана»

    O->>E: выбрать свободную единицу перфоратора (I3)
    E-->>O: единица, состояние «Свободен»

    Note over O,E: Проверка на дефекты при выдаче обязательна (D11, I13)
    O->>E: проверить дефекты
    E-->>O: дефектов нет

    O->>P: принять оплату N суток x 500 ₽ (D8, I8)
    P-->>O: оплата принята
    O->>J: запись «оплата принята»

    O->>A: создать аренду (датаВыдачи = сейчас, D6)
    A->>E: занять единицу
    E-->>A: состояние «ВАренде» (I1, I2)
    A->>Z: закрыть заявку
    Z-->>O: заявка «Закрыта» (I12)
    O->>C: выдать инструмент (D5)
    O->>J: запись «выдача»

    Note over A: время аренды, не более 21 сутки с продлением (D3, I8)

    C->>O: вернуть инструмент
    O->>E: проверить дефекты при приёме (D11)
    E-->>O: дефектов нет
    O->>A: завершить аренду (датаВозврата = сейчас)
    A->>E: освободить единицу
    E-->>A: состояние «Свободен» (I2)
    A->>D: вернуть залог полностью (одно действие, D13, I15)
    D-->>C: 3000 ₽
    O->>J: запись «приём, возврат залога»
```

## Ветка A: отклонение заявки

**Вопрос:** Как отклоняется заявка и кто в этом случае возвращает залог?

```mermaid
sequenceDiagram
    autonumber
    actor O as Оператор
    participant Z as Заявка
    participant D as Залог
    participant J as Журнал

    Note over O,Z: Заявка в статусе «ОжидаетОбработки» или «ЗалогВнесён» (I11)
    O->>Z: отклонить заявку
    Z-->>O: статус «Отклонена» (I10, терминальный)

    alt залог был внесён
        O->>D: вернуть залог полностью (D7)
        D-->>O: возврат выполнен (I6)
    end

    O->>J: запись «заявка отклонена, залог возвращён»
```

## Ветка B: приём с дефектом

**Вопрос:** Что делает оператор, если возвращённый инструмент оказался с дефектом?

```mermaid
sequenceDiagram
    autonumber
    actor C as Клиент
    actor O as Оператор
    participant A as Аренда
    participant D as Залог
    participant E as Единица
    participant F as Дефект
    participant J as Журнал

    C->>O: вернуть шлифмашинку
    O->>E: проверить дефекты при приёме (D11)
    E-->>O: обнаружен дефект

    O->>F: зафиксировать дефект, суммаУщерба = S ₽ (I13)
    F-->>O: дефект записан

    O->>A: завершить аренду

    alt S не больше залога 2000 ₽
        O->>D: удержать S, вернуть остаток 2000 - S (I7, I14)
        D-->>C: остаток залога
    else S больше залога
        Note over O,D: Удерживается максимум весь залог (I14), излишек моделью не учитывается
        O->>D: вернуть 0 ₽
    end

    O->>E: перевести в состояние «Неисправен» (D12)
    O->>J: запись «приём с дефектом, удержание S»
```

## Примечания

- Оплата и залог — разные потоки денег и не компенсируют друг друга (I9).
- Выдача возможна только при одновременном выполнении I5: залог + оплата + статус `Обработана`.
- Просрочка аренды и «висячие» заявки на диаграммах не показаны — в модели отсутствуют.
